# Add an explicit CANCEL message, reversing the original timeout-only design

ADR-0003 deliberately omitted an unregister message: a Client that stopped running just stopped renewing, and the Server reaped it via Redis TTL. The Client's benchmark/simulation requirements now explicitly call for "voluntary registration cancellation" as a first-class, measurable behavior (the benchmark harness needs to exercise and time it, not just let it happen implicitly via process exit). We're reversing that original decision and adding `CANCEL_REQUEST(clientId)` / `CANCEL_RESPONSE(status)` to the wire protocol, mirroring `RENEW`'s symmetry: cancelling a Client ID with no live Registration returns `NOT_REGISTERED`. On success, the Server deletes the Redis key outright rather than waiting for its TTL.
